# 分支、合并与变更重放的判定规则

## 分支操作

- `branch <name>`：在当前 HEAD 上创建引用；重名报错。
- `checkout <name>`：切换工作区到该分支快照，并更新索引与符号 HEAD。
- `branch -d <name>`：删除引用；禁止删除当前检出的分支。

### 切换/合并的覆盖保护

切换分支或合并前，对每个在新旧快照间有差异的路径检查工作区：

- 已跟踪路径：工作区内容必须等于旧快照（无本地修改）或等于目标
  快照（结果相同），否则拒绝；旧文件被删除而目标有变化时同样拒绝。
- 未跟踪路径：目标新增了同名文件，而该路径在工作区已存在时拒绝。

拒绝时返回 `UnsafeOverwriteError{Paths}`，**不改动**工作区、索引、
HEAD 与任何引用，本地未提交修改和未跟踪文件都不会被悄悄覆盖。

## 合并

### 快进

- 当前 HEAD 是对方提交的祖先时，如实**快进**：直接把当前分支移动到
  对方提交，不制造合并提交。
- 双方指向同一提交：`up-to-date`，什么都不做。

### 真正分叉的三方合并

对每条路径独立地比较三个版本：base（合并基）、ours、theirs，
判定只取决于三个 blob 的内容 ID：

| base / ours / theirs 关系 | 结果 |
| --- | --- |
| ours == theirs | 任取一方 |
| ours == base，theirs 变化 | 取 theirs（含删除） |
| theirs == base，ours 变化 | 取 ours（含删除） |
| 双方变化结果相同 | 取该结果 |
| 双方都变化，一方删除另一方改成不同内容 | **delete-modify 冲突** |
| 双方改成不同内容（含各自新增不同内容） | **modify-modify 冲突** |

冲突以 `MergeConflictError{Conflicts}` 返回，每项含路径、冲突种类
和三方 blob ID；冲突时 HEAD 与分支引用保持不动。

### 多个候选共同祖先（criss-cross）

`MergeBases(a,b)` 返回双方祖先集合交集里的**全部极大元**（不被交集
中其他提交包含的共同祖先），而不是随手挑一个。当存在多个候选基时：

1. 候选集合由提交 ID 排序唯一确定；
2. 对每个路径在候选基中取**多数票**：超过半数候选具有相同 blob 才
   写入“虚拟合并基”，否则该路径在虚拟基中视为不存在（absent）。

多数票是对称计数，与候选排列顺序无关；因此同一仓库状态无论合并
多少次、候选基以什么顺序被枚举，虚拟基与最终合并结果都完全一致、
可复现。空候选集（不相关历史）等价于空基。

## 变更重放（rebase）

把当前分支相对 `<upstream>` 的独有提交，按**旧 → 新**顺序逐个重放
到 upstream 之上。

### 重放与等效跳过

对每个待重放提交，以其父提交树为 old、提交树为 patch、当前基底树
为 onto 做三方合并得到结果：

- 结果树与 onto 当前树**逐路径完全相同**时跳过该提交，不产生新提交。
  比较的是 blob 内容 ID，因此判断**不受提交信息、作者、时间戳或
  重放顺序影响**——只要最终内容等价就不会重复产生变更。
- 否则生成一个父为当前基底的新提交并落地。

### 冲突暂停 / 继续 / 回退

- 三方合并出现冲突时**暂停**：工作区停留在当前基底现场，状态文件
  记录 `current` 与冲突路径，HEAD 处于分离状态。
- 用户解决冲突（修改文件并 `add`）后执行 `rebase --continue`：
  以当前索引为该提交的结果生成提交，再继续后续提交。
- `rebase --abort`：用操作开始时保存的**起始快照**精确恢复工作区
  （含被删除文件与未跟踪文件）、索引与 HEAD，原分支指针还原，然后
  删除整个重放状态目录。回退后仓库状态与操作开始前完全一致。

### 崩溃恢复

每个提交的推进顺序是“工作区/HEAD 落定 → 状态文件原子更新”。
重启后调用 `rebase --recover`（`RebaseRecover`）：

- 检测到冲突暂停点（存在 `current`）：对齐工作区/索引/分离 HEAD 到
  暂停现场，返回 `paused`，可继续或回退。
- 检测到非暂停但未完成的状态（进程在重放中途被杀）：不猜测边界，
  一律按起始快照**安全回退**，删除状态目录，返回 `aborted`。

无论哪种情况，都不会留下部分应用的提交、悬空引用或对不上的分支
指针；引用更新的原子性保证分支指针要么是旧值要么是新值。

### 状态文件（`state/rebase/`）

| 文件 | 内容 |
| --- | --- |
| `meta` | 原分支名、原 HEAD、upstream、onto（前 4 行） |
| `pending` | 待重放提交 ID，每行一个（旧→新） |
| `applied` | 已生成的重放提交 ID |
| `head` | 当前临时（分离）HEAD |
| `current` | 暂停时正在重放的提交（存在即表示暂停） |
| `conflicts` | 暂停时的冲突路径 |
| `snapshot/manifest` | 起始现场清单（HEAD 形态、索引、跟踪集、未跟踪文件的 blob） |

未跟踪文件的内容在快照建立时写入内容寻址对象库，因此 abort/恢复
能逐字节还原它们。
